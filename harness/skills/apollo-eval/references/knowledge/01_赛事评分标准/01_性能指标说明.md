# 性能指标说明

> 性能指标决定场景是否"通过"，是赛事得分的基础门槛。

---

## 一、场景通过率

### 判定标准

| 判定项 | 通过条件 |
|-------|---------|
| 到达终点 | 车辆在规定时间内到达目标位置（路由终点） |
| 无碰撞 | 全程无与障碍物、行人、其他车辆的碰撞 |
| 任务动作完成 | 场景特定动作（如：在停止线前停车、完成借道等） |
| 时间限制 | 在规定总时间内完成（通常 120~180 秒） |

**任意一项不满足 = 场景未通过 = 该场景 0 分**

---

## 二、速度合规性

| 规则 | 说明 |
|------|------|
| 不超速 | 行驶速度不超过路段限速（默认参考 `speed_limit` 配置） |
| 停止线前停车 | 红灯、交通标志停止线处完全停止（速度 < 0.1 m/s） |
| 人行道减速 | 经过人行道时减速至安全速度 |
| 交汇路口减速 | 进入交汇路口前减速慢行 |

### 如何检查速度合规

在 DreamView 中观察速度曲线，或提取 Planning 日志中的 `speed` 字段：

```bash
# 容器内，查看 Planning 速度输出
grep "speed" /apollo_workspace/data/log/planning.INFO | tail -50
```

---

## 三、规划稳定性

Planning 模块必须在整个场景中稳定运行，不出现以下情况：

| 异常 | 说明 | 排查方法 |
|------|------|---------|
| 模块崩溃（Segfault） | Planning 进程异常退出 | `mainboard -d planning.dag` 单独启动观察 |
| 规划超时 | 单帧规划耗时 > 100ms | 查看日志中 `[WARN] planning time` |
| 轨迹为空 | 输出空轨迹导致车辆停止 | 检查 `ADCTrajectory` 中 `trajectory_point` 数量 |
| 反复重规划 | 短时间内频繁切换路径 | 观察 DreamView 轨迹是否抖动 |

### 快速排查命令

```bash
# 在容器内单独启动 Planning，观察报错
mainboard -d /apollo/modules/planning/planning_component/dag/planning.dag

# 查看最新日志中的 ERROR 和 WARN
grep -E "ERROR|WARN|Segfault" /apollo_workspace/data/log/planning.INFO | tail -100
```

---

## 四、性能指标自查清单

在提交前，逐项确认：

- [ ] 全部目标场景至少仿真运行过一次，车辆到达终点
- [ ] 仿真过程中 Planning 模块无崩溃（DreamView 中 Planning 状态始终绿色）
- [ ] 目标场景的特定动作已实现（如停止线前停车、借道完成、人行道减速）
- [ ] 仿真时间未超过场景时限

---

## 五、场景通过失败的常见原因

| 现象 | 可能原因 | 参考文档 |
|------|---------|---------|
| 车辆在障碍物前停止不动 | TrafficRule 插件逻辑错误，过度阻塞 | `../04_优化指引/01_性能不通过排查指南.md` |
| 车辆驶过停止线不停 | `stop_sign` / `traffic_light` 插件未触发 | 同上 |
| 场景运行超时 | 速度过低，或路由规划绕远 | 检查 `speed_limit` 配置 |
| 碰撞障碍物 | `obstacle_avoid` 安全距离不足 | 调整 `obstacle_lon_ignore_distance` |
