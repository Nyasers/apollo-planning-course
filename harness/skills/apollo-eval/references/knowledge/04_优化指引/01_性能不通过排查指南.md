# 性能不通过排查指南

> 当场景仿真未通过（车辆未到达终点、发生碰撞、超时）时，按本指南逐步排查原因。

---

## 一、快速诊断流程

```
场景未通过
    ↓
1. 查看 DreamView：车辆停在哪里？
    ↓
2. 查看 Planning 日志：有报错吗？
    ↓
3. 用 mainboard 单独启动 Planning，观察详细输出
    ↓
4. 对照下方常见原因表定位问题
    ↓
5. 修复 → 重新仿真 → 验证
```

---

## 二、常见原因与解决方案

### 2.1 车辆在某位置停止不动

| 可能原因 | 判断方法 | 解决方案 |
|---------|---------|---------|
| TrafficRule 插件过度阻塞 | 日志搜索 `STOP` 关键词，看是哪个 rule 产生了 stop decision | 调整对应 rule 的 `stop_distance` 或 `stop_condition` |
| 障碍物被误判为阻塞 | DreamView 中查看 Prediction 层，看障碍物预测轨迹 | 调整 `obstacle_lon_ignore_distance` 或感知置信度阈值 |
| 路由失效 / 终点不可达 | 日志搜索 `routing` 或 `no valid path` | 重新在 DreamView 中设置路由终点 |
| Profile 配置被覆盖 | 执行 `aem profile use default` 后重试 | **每次编译后必须执行** `aem profile use default` |

```bash
# 搜索 stop decision 来源
grep -i "stop_reason\|STOP\|stop_decision" /apollo_workspace/data/log/planning.INFO | tail -50
```

### 2.2 车辆发生碰撞

| 可能原因 | 判断方法 | 解决方案 |
|---------|---------|---------|
| 障碍物避让距离不足 | DreamView 中观察碰撞时刻的轨迹 | 增大 `min_stop_distance_obstacle`、`lateral_obstacle_ignore_distance` |
| 速度过高进入危险区域 | 查看碰撞时的速度值 | 增加该区域的速度限制或障碍物减速策略 |
| 借道场景判断时机过晚 | 观察换道决策时刻 | 调整 `lane_change_prepare_length` 增大准备距离 |
| 插件 Bug 导致错误决策 | `mainboard` 单独启动查看 Segfault | 检查自定义插件中的指针操作和边界条件 |

### 2.3 场景超时

| 可能原因 | 判断方法 | 解决方案 |
|---------|---------|---------|
| 速度限制过低 | 观察仿真中车速是否全程 < 2 m/s | 检查 `planning.pb.txt` 中的 `speed_limit` 或 profile 中的限速配置 |
| 车辆反复 stop/go | DreamView 中观察车辆是否来回停启 | 见 2.1 车辆停止不动的排查 |
| 路由绕远 | DreamView 中观察路由路径 | 重新规划路由，或检查地图是否正确加载 |

### 2.4 Planning 模块崩溃（Segfault / 未启动）

```bash
# 单独启动 Planning 查看详细报错
mainboard -d /apollo/modules/planning/planning_component/dag/planning.dag

# 常见报错及修复
# "Cannot find WORKSPACE" → 不在 /apollo_workspace 目录下
# "Segmentation fault" → 代码中有非法内存访问，检查自定义插件
# 配置文件解析失败 → 检查 .pb.txt 文件语法
```

**Planning 完整恢复流程** → 参考 `apollo-dev/references/knowledge/07_FAQ故障排查/planning模块打不开恢复指南.md`

## 三、分场景排查指南

### 人行道（Crosswalk）场景未通过

```bash
grep "crosswalk" /apollo_workspace/data/log/planning.INFO | tail -30
```

常见问题：
- 人行道附近行人障碍物触发永久停车：调整 `crosswalk_statics_obs_stop_dist` 或行人等待超时参数
- 车辆未减速直接通过：检查 `CROSSWALK` rule 是否在 `traffic_rule_config.pb.txt` 中启用

### 借道绕行（Lane Borrow）场景未通过

```bash
grep -i "borrow\|lane_change\|LANE_BORROW" /apollo_workspace/data/log/planning.INFO | tail -30
```

常见问题：
- 借道条件未触发：检查 `lane_borrow_decider_config` 中的触发距离和障碍物类型
- 借道后无法回正：调整 `back_to_inlane_distance`

### 交汇路口（Junction）场景未通过

```bash
grep -i "junction\|yield\|intersection" /apollo_workspace/data/log/planning.INFO | tail -30
```

常见问题：
- 交汇口永久停车：检查 `YIELD_SIGN` 或 `TRAFFIC_LIGHT` rule 的等待超时设置
- 未减速直接冲过：检查 `junction_stop_distance` 配置

### 自主泊车（Valet Parking）场景未通过

```bash
grep -i "parking\|valet\|park_and_go" /apollo_workspace/data/log/planning.INFO | tail -30
```

常见问题：
- 泊车场景未触发：检查 profile 中泊车场景配置是否正确加载
- 泊车路径规划失败：检查泊车位地图标注和车辆当前位置

## 四、通用排查命令速查

```bash
# 1. 查看当前 profile 是否正确加载
aem profile use default && cat profiles/default/current_profile

# 2. Planning 模块状态
mainboard -d /apollo/modules/planning/planning_component/dag/planning.dag 2>&1 | head -50

# 3. 最近的 ERROR 日志
grep "ERROR" /apollo_workspace/data/log/planning.INFO | tail -20

# 4. 最近 stop decision
grep "stop_reason" /apollo_workspace/data/log/planning.INFO | tail -20

# 5. 查看轨迹是否有输出
cyber_tools echo --channel /apollo/planning/trajectory 2>&1 | head -30
```

## 五、修复后验证步骤

```
1. aem profile use default        # 确保 profile 配置生效
2. aem bootstrap start --plus     # 启动 DreamView
3. 在 DreamView 中重新运行目标场景
4. 观察车辆行为，确认问题解决
5. 如已录包，运行 extract_metrics.py 验证体感指标
```
