# 仿真不通过排查指南

> 当集成测试（DreamView + SimControl 仿真）场景未通过时，使用本指南快速定位问题。

> 注意：本文聚焦于**测试角度**的排查（确认是代码问题还是测试环境问题）。完整的场景性能排查见 `apollo-eval/references/knowledge/04_优化指引/01_性能不通过排查指南.md`。

---

## 一、仿真不通过 vs 测试环境问题

首先区分问题来源：

| 现象 | 可能原因 | 判断方法 |
|------|---------|---------|
| 以前通过，现在不通过 | 代码改动引入 Bug | `git diff` 查看改动 |
| 从未通过过 | 功能未实现或配置缺失 | 对照场景要求检查代码 |
| 每次结果不一样 | 测试环境未重置 | 重启 DreamView 后再测 |
| Profile 改动后不通过 | 参数调整引入问题 | `git diff profiles/default/` |

---

## 二、Git Bisect 定位代码问题

如果仿真之前通过，最近改动后不通过：

```bash
# 在宿主机执行（不在容器内）
git log --oneline -10   # 找到最后通过的 commit

# 回退到最后已知通过的版本测试
git stash                    # 暂存当前改动
git checkout <known_good_commit>
# 重新进容器测试：aem start && aem enter && buildtool build -p modules/planning/
# 仿真验证...

# 恢复改动
git stash pop
```

---

## 三、Profile 改动导致的不通过

```bash
# 查看 profile 改动
git diff profiles/default/

# 回退 profile 到上一个版本
git checkout HEAD -- profiles/default/

# 重新加载
aem profile use default

# 再次仿真验证
```

---

## 四、测试环境重置步骤

当仿真结果不稳定时，完整重置环境：

```bash
# 容器内
# 1. 停止 DreamView
aem bootstrap stop

# 2. 清理临时数据（可选，谨慎操作）
rm -f /apollo_workspace/data/log/planning.*

# 3. 重新加载 profile
aem profile use default

# 4. 重启 DreamView
aem bootstrap start --plus

# 5. 等待 10 秒后再运行场景
```

---

## 五、对比测试法

当不确定是哪次改动引入问题时，用对比法快速定位：

```bash
# 1. 记录当前改动
git stash

# 2. 用原始代码测试（确认问题存在于改动中）
buildtool build -p modules/planning/
aem profile use default
# 在 DreamView 中测试 → 如果通过，说明问题在改动中

# 3. 恢复改动
git stash pop

# 4. 逐步还原各个文件，找到罪魁祸首
git checkout HEAD -- modules/planning/traffic_rules/crosswalk/crosswalk.cc
# 测试...
```

## 六、常见集成测试不通过原因总结

| 原因 | 发现方法 | 解决方案 |
|------|---------|---------|
| 编译后未重置 profile | 检查 `aem profile use default` 是否执行 | 执行 `aem profile use default` |
| 插件 condition 写反 | 代码审查，加日志 | 修复 condition 逻辑 |
| 距离阈值设置过大/过小 | 对比参数值与场景实际距离 | 调整阈值参数 |
| 场景 ID 与 DreamView 不对应 | 检查场景插件版本 | 重新下载场景插件 |
| DreamView 地图未加载 | DreamView 地图区域显示空白 | 见 apollo-dev FAQ：dreamview地图不加载 |
| Planning 进程崩溃 | DreamView 中 Planning 状态变红 | `mainboard -d planning.dag` 排查 |
