各位评审老师好，这里介绍“城市道路自动驾驶综合仿真实验”。它不是概念动画，而是把 Apollo 仿真、真实 record、评分报告和 AI 问答连成一条可操作的实验链路。视频大约三分钟，我会先说明为什么做，再展示当前已经跑通的部分和后续规划。

01 / The Problem

自动驾驶教学，不能只停留在演示。

真实车辆和真实道路能带来临场感，但很难支撑每一位学生反复试错、观察和复盘。

PAIN 01

成本高

车辆、传感器、测试场地和维护周期，限制了实验规模和开放频次。

PAIN 02

难复现

行人、车辆、信号灯和天气每次都在变化，同一个实验很难稳定重跑。

PAIN 03

AI 在旁观

如果 AI 只是一张聊天侧栏，就无法真正进入实验过程、证据和评价。

自动驾驶教学最大的矛盾，是真实世界很有价值，但真实世界很难被每个学生稳定重复。我们需要一个虚拟实验场：场景可以重跑，数据可以检查，错误可以修复，AI 也能参与进来。

02 / Project Positioning

把 Planning 实验，搬进可运行的仿真环境。

以 Apollo Planning 为核心，连接定位、感知、预测、控制与仿真平台，让学生完成一次可复核的城市道路自动驾驶实验。

智能车辆 / 车辆工程 / 自动化本科二年级以上单场景约 45 分钟
SCENARIO → STAGE → TASK
项目定位不是泛泛的自动驾驶展示，而是围绕 Planning 设计一条学生可以亲手完成的实验路径。首个人行道避让场景同时涉及场景、规控、速度和安全评价，适合作为入门综合案例。

03 / Learning Loop

每一步，都留下证据。

01

环境检查

确认 Docker、aem、Apollo 和 DreamView 可用。

02

运行场景

启动地图、SimControl 和规划控制模块。

03

录制数据

采集 planning、control、localization 等核心 channel。

04

评分诊断

检查 TTC、加速度、Jerk、急刹和失败帧。

05

优化复跑

修改配置或代码，再次验证，形成前后对比。

这条闭环是项目的骨架：环境、场景、录制、评价、优化。每一步都不是只看结果，而是留下可以复查的文件。这样学生交上来的不是一张截图，而是一条能够说明“我做了什么、为什么这样改”的证据链。

不是网页模拟，是真实 Apollo
工具链。

网页负责课程、任务和报告展示；真实仿真、record、评分和 AI 报告问答在本地 Harness 中完成。

这里要强调：真实实验不是网页里的动画，而是本地 Apollo 工具链。学生会在 DreamView 里启动场景，用 cyber record 留下真实数据，再由评价脚本和 Harness 生成报告。网页只负责教学呈现和结果展示。

05 / Apollo Claw

AI 不是侧边栏，是实验过程的协作者。

SKILL 01
apollo-env

环境体检

检查 Docker、aem、buildtool 和 DreamView，解释环境失败原因。

SKILL 02
apollo-dev

代码与配置定位

围绕 Scenario、Stage、Task、参数和日志，给出最小排查路径。

SKILL 03
apollo-test

录包与证据整理

生成 record、channel 汇总、CSV 和图表，帮助确认数据是否有效。

SKILL 04
apollo-eval

评分与解释

解释 TTC、加速度、Jerk、急刹和未通过帧，提出下一轮优化方向。

Harness 中的报告问答会读取当前实验报告和最近对话；未配置 DeepSeek 时自动使用规则回答，评分仍由脚本和教师负责。
Apollo Claw 的四个技能分别覆盖环境、开发、测试和评价。它不是替学生做实验，而是把“下一步该看什么、为什么失败、如何验证”变成可以追问的过程。AI 的答案绑定当前报告，不能脱离证据自由发挥。
