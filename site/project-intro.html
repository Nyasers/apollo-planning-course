01 / The Problem

自动驾驶教学，不能只停留在演示。

真实车辆和真实道路能带来临场感，但很难支撑每一位学生反复试错、观察和复盘。

PAIN 01

成本高

车辆、传感器、测试场地和维护周期，限制了实验规模和开放频次。

PAIN 02

难复现

行人、车辆、信号灯和天气每次都在变化，同一个实验很难稳定重跑。

PAIN 03

AI 在旁观

如果 AI 只是一张聊天侧栏，就无法真正进入实验过程、证据和评价。

真实车辆成本高、场景难复现，AI 往往只在旁边聊天。我们需要一个可重复、可观察、可评价的虚拟实验场。

02 / Project Positioning

把 Planning 实验，
搬进可运行的仿真环境。

以本地 Linux 仿真、远程自学课程网站和本地 Apollo_Harness 实验助手为支撑，围绕 Planning 连接定位、感知、预测、控制与仿真平台，让学生完成可复核的城市道路自动驾驶实验。

05 / Apollo_Harness

Apollo_Harness，实验过程的 AI 主线。

本地技能执行器 + 证据存储 + DeepSeek 解释器，围绕环境、代码、数据和评分形成可追溯的实验协作链。

SKILL 01
apollo-env

环境体检

检查 Docker、aem、buildtool 和 DreamView，解释环境失败原因。

SKILL 02
apollo-dev

代码与配置定位

围绕 Scenario、Stage、Task、参数和日志，给出最小排查路径。

SKILL 03
apollo-test

录包与证据整理

生成 record、channel 汇总、CSV 和图表，帮助确认数据是否有效。

SKILL 04
apollo-eval

评分与解释

解释 TTC、加速度、Jerk、急刹和未通过帧，提出下一轮优化方向。

Apollo_Harness 读取当前报告并支持 DeepSeek 报告问答；AI 只提出建议，学生确认后执行，教师保留最终评价权。
Apollo_Harness 用 env、dev、test、eval 四类技能做环境体检、代码定位、录包整理和评分解释；AI 只给建议。

09 / Architecture

三层架构，把仿真、AI 和教学分开。

网页不承担仿真计算；真实运行发生在本地 Apollo，Harness 把证据整理成可解释、可复核的报告。

01课程网站：21 课、实验中心、报告展示；不接收 API Key，不上传学生数据。
02本地 Apollo_Harness：127.0.0.1:8765；env / dev / test / eval 四技能；白名单命令与人工确认。
03Apollo 仿真容器：WSL2 / Ubuntu + DreamView + SimControl + Cyber Record，产生真实 channel 数据。
04证据契约：doctor.json → record → channel_summary.csv → report.json / report.md → plots。
边界：脚本产出事实，模型解释事实，学生确认操作，教师保留最终评价权。
架构分三层：网站负责课程与报告，Harness 负责环境、代码、数据和评分辅助，Apollo 容器负责真实仿真。
