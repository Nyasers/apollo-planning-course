AI Assistance Loop

AI 辅助实验闭环

从环境检查到报告复盘，Apollo Claw 在 8 个阶段留下可追溯的技能、证据和验证结果。

01

实验准备

生成预习检查清单，明确实验目标、场景和交付证据。

apollo-env产出：预习检查清单
02

环境检查

检查 Ubuntu、WSL2、Docker、aem、磁盘和 Apollo 容器状态，解释失败原因。

apollo-env产出：doctor.json / 环境报告
03

场景运行

提示 DreamView 入口、场景状态和运行前检查项。

apollo-dev产出：运行状态记录
04

观察问题

从 planning、control 日志中提取减速偏晚、急刹和 TTC 偏低等线索。

apollo-dev产出：日志摘要
05

诊断定位

定位 crosswalk 场景、TrafficRule、速度边界和任务管线中的相关配置。

apollo-dev产出：代码/配置位置
06

录制与可视化

按 pnc profile 录制 record，盘点 channel，生成 CSV、PNG 和 Markdown 报告。

apollo-test产出：record / CSV / PNG
07

评分与优化

解释 TTC、加速度、Jerk、急刹和场景得分，给出下一轮最小改动建议。

apollo-eval产出：评分解释与优化建议
08

报告与复盘

汇总 AI 建议、学生操作、证据链和优化前后对比，形成实验报告和能力画像。

apollo-test + apollo-eval产出：report.md / 能力画像

Local Harness

本地环境与 Harness

推荐使用预装 Ubuntu 镜像；也可以使用 WSL2 或 Ubuntu 虚拟机手动搭建。真实实验在本地 Harness 面板完成。

推荐 · 准备中

预装 Ubuntu 镜像

镜像发布后将包含 Docker、AEM、Apollo 容器、application-pnc、编译缓存、Apollo Claw 四技能和 Harness。

  • 离线导入镜像
  • 启动脚本自检
  • 本地 DeepSeek Key 配置
查看导入说明

WSL2 手动安装

适合熟悉命令行的学生。需要在 WSL2 中验证 Docker、AEM、GUI 和 DreamView 端口。

  • Ubuntu 22.04
  • Docker Engine
  • application-pnc + buildtool
查看第 00 课

Ubuntu 虚拟机手动安装

兼容性通常更好，适合第一次接触 Linux 的学生，但虚拟磁盘和内存占用更高。

  • VMware / VirtualBox
  • 建议 16GB 内存
  • 建议 55GB 以上虚拟磁盘
